# Survivor player character, held items and flare (v2)
- Date: 2026-11-18
- Status: Superseded by v3
- Changes from v1: per the user's feedback, picking up an item now stows the held item into a new small fixed-slot
  `UInventoryComponent` (3 slots) instead of dropping it. A lit flare can't be stowed, so it's dropped; a full
  inventory also drops. Added inventory input (wheel, 1-3, H to stow) and an inventory row in the HUD.
- Approved by the user on 2026-11-18. Backfilled on 2026-11-19 verbatim from the approved plan-mode file.

## Context
EndlessOcean needs its own first-person player character for the sinking-ship loop. The template
characters (`AEndlessOceanCharacter`, `AHorrorCharacter`) are built around a skeletal arms mesh and a
"head" socket, and mix logic into the character. We'll build a new, component-based character that
can be extended later (hiding, oxygen, repair tools) without rewrites. Visuals are grey primitives
for now; a visual pass (one/two-handed poses, arms) comes later.

Decisions from the user:
- **Limited mobility:** no jumping, slow walk + short stamina sprint, crouch, heavy head-bob/sway
  that the player can **toggle off**.
- **Each flare is a held item** you pick up from the world.
- **One held item at a time, plus a small limited inventory.** Picking up something else **stows** the held item into
  the inventory, **except a lit flare, which is dropped** (it can't be stowed). If the inventory is full, the held item
  is dropped instead.
- Flare: **single use, 30 s burn**. Hold it for light, or **throw** it to keep it burning on the floor.

Scope estimate: medium (≈2 days of C++ plus editor setup). No deadline risk.

## New C++ (all new files, runtime module)

### `Source/EndlessOcean/Player/`
- **`SurvivorCharacter.h/.cpp`: `ASurvivorCharacter : ACharacter`**. Thin: it owns components and binds input.
  - Components: `UCameraComponent` (on capsule at eye height, `bUsePawnControlRotation`), `USceneComponent HandAnchor`
    (child of camera, where held items attach), `UStaminaComponent`, `UInteractionComponent`, `UItemHolderComponent`.
  - Uses the `FObjectInitializer` constructor with `SetDefaultSubobjectClass<USurvivorMovementComponent>` to swap in the
    custom movement component (teaching point: how Unreal replaces default subobjects).
  - No jumping: override `CanJumpInternal_Implementation` → `false`, and no jump binding.
  - Crouch: `bCanCrouch`, `CrouchedHalfHeight`, `bToggleCrouch` option (hold vs toggle).
  - Also owns `UInventoryComponent`.
  - Input (`TObjectPtr<UInputAction>`): Move, Look, MouseLook, Sprint, Crouch, Interact, UseItem, ThrowItem, DropItem,
    CycleInventory (mouse wheel, axis), SelectSlot (keys 1–3), StowItem (H, empty hands).
    Handlers forward to components (`ItemHolder->UseHeldItem()` and so on).
  - Wires delegates: movement `OnSprintStateChanged` → `Stamina->SetDraining`; stamina `OnExhaustedChanged` →
    `Movement->SetSprintBlocked`.
- **`SurvivorMovementComponent.h/.cpp`: `USurvivorMovementComponent : UCharacterMovementComponent`**
  - `bWantsToSprint`, `SprintSpeed`, `bSprintBlocked`; override `GetMaxSpeed()` so sprint speed applies only when
    sprinting is allowed (on the ground, not crouched, moving forward-ish, not blocked).
  - Walk speed kept low (`MaxWalkSpeed` ≈ 220, `MaxWalkSpeedCrouched` ≈ 120, slower acceleration for weight).
  - Broadcasts `OnSprintStateChanged(bool)` when the *effective* sprint state changes (checked in `OnMovementUpdated`).
- **`StaminaComponent.h/.cpp`: `UStaminaComponent : UActorComponent`** (reusable, no Tick)
  - `MaxStamina`, `DrainRate`, `RegenRate`, `RegenDelay`, `RecoverThreshold` (fraction you must regain before sprinting again).
  - A fixed-rate `FTimerHandle` runs only while draining or regenerating; stops when full.
  - Delegates `OnStaminaChanged(float Normalized)`, `OnExhaustedChanged(bool)`.
- **`SurvivorCameraModifier.h/.cpp`: `USurvivorCameraModifier : UCameraModifier`** (`Blueprintable`)
  - Head-bob (speed-scaled, separate walk/sprint/crouch amplitudes), strafe roll/sway, and **look lag** (view rotation
    trails control rotation for a heavy feel without changing aim).
  - Toggle: the camera modifier's own enable/disable. The default comes from `USurvivorSettings`, and the console variable
    `eo.CameraMotion 0/1` changes it at runtime. Later an options menu calls the same function.
- **`SurvivorPlayerController.h/.cpp`: `ASurvivorPlayerController : APlayerController`**
  - Adds mapping contexts (`TArray<TObjectPtr<UInputMappingContext>>`), adds the camera modifier class in `BeginPlay`,
    `UFUNCTION(BlueprintCallable) SetCameraMotionEnabled(bool)`, creates the HUD widget.
- **`SurvivorSettings.h/.cpp`: `USurvivorSettings : UDeveloperSettings`** (`Config=Game, defaultconfig`):
  `bCameraMotionEnabledByDefault`, interaction trace channel. Shows in Project Settings → Game → Survivor.
- **`SurvivorHUDWidget.h/.cpp`: `USurvivorHUDWidget : UUserWidget`** (small). Binds to the stamina, interaction-focus and
  held-item delegates and exposes `BlueprintImplementableEvent`s (`OnStaminaChanged`, `OnInteractPromptChanged`,
  `OnHeldItemChanged`, `OnFlareTimeChanged`), so the widget BP only handles layout.

### `Source/EndlessOcean/Interaction/`
- **`Interactable.h`: `UInteractable`/`IInteractable` interface** (`BlueprintNativeEvent`s): `CanInteract(AActor* Instigator)`,
  `Interact(AActor* Instigator)`, `GetInteractionPrompt()`. Future doors, valves and repair points use the same interface.
- **`InteractionComponent.h/.cpp`: `UInteractionComponent : UActorComponent`**
  - A timer-driven (≈15 Hz, configurable) line trace from the view point on a new **`Interaction` trace channel**, with
    `TraceDistance`. Tracks the focused interactable as a `TWeakObjectPtr` and broadcasts `OnFocusChanged`.
  - `TryInteract()`; debug draw controlled by the console variable `eo.Interaction.Debug`.

### `Source/EndlessOcean/Items/`
- **`ItemDefinition.h/.cpp`: `UItemDefinition : UPrimaryDataAsset`**: `DisplayName`, `EItemHandedness {OneHanded, TwoHanded}`
  (stored now and used by the visual pass), `HeldOffset` (FTransform), `ThrowSpeed`, `DropSpeed`.
- **`HeldItem.h/.cpp`: `AHeldItem : AActor`** (abstract, implements `IInteractable`)
  - Root `UStaticMeshComponent` (physics simulated when in the world, off when held), `TObjectPtr<UItemDefinition> Definition`.
  - Virtuals: `OnPickedUp(UItemHolderComponent*)`, `OnReleased(bool bThrown)`, `UsePrimary()`, `CanBePickedUp()`.
  - `Interact` → finds the instigator's `UItemHolderComponent` and asks it to pick this up.
  - Delegate `OnItemStateChanged` (for UI and future AI hooks).
- **`ItemHolderComponent.h/.cpp`: `UItemHolderComponent : UActorComponent`** (the hand)
  - `TObjectPtr<AHeldItem> HeldItem`, `SetHandAnchor(USceneComponent*)`.
  - `PickUp(AHeldItem*)`: if something is already held, it's stowed in the inventory if `CanBeStowed()`
    and there's room; otherwise it's dropped. Then the new item goes into the hand.
  - `UseHeldItem()`, `DropHeldItem()`, `ThrowHeldItem()` (detach, enable physics, velocity along the view direction,
    ignore owner collision briefly), `StowHeldItem()` (empty hands), `EquipFromInventory(int32 Slot)`, `CycleInventory(int32 Dir)`.
  - `OnHeldItemChanged(AHeldItem* New, AHeldItem* Old)`.
- **`InventoryComponent.h/.cpp`: `UInventoryComponent : UActorComponent`** (small, limited stowed storage)
  - `TArray<TObjectPtr<AHeldItem>> Slots`, `Capacity` (default 3, clamped 1–8). `TryAdd`, `RemoveAt`, `HasRoom`,
    `GetItems`. Delegate `OnInventoryChanged`.
  - Stowed items stay alive as actors (so their state is kept) but are hidden, with collision and physics off,
    attached to the owner. Kept separate from the hand so other systems (repair needing a part, the HUD) can query it.
  - Later: a weight or slot-size cost per item (two-handed items take 2 slots) via `UItemDefinition`. Not in this pass.
- `AHeldItem::CanBeStowed()` is virtual (default true). `AFlareItem` returns false while `Burning`, so a lit flare is
  dropped when you pick up something else.
- **`FlareItem.h/.cpp`: `AFlareItem : AHeldItem`**
  - `EFlareState {Unlit, Burning, BurntOut}`. Grey cylinder mesh with a red cap (engine basic shapes plus a dynamic material instance).
  - `UPointLightComponent` (off until lit). Tuning: `BurnDuration` = **30 s** (`Units="s"`, clamps), `LightColor`,
    `Intensity`, `AttenuationRadius`, `FlickerAmount`/`FlickerRate` (timer-based flicker, `EditCondition` on `bFlicker`),
    `FadeOutTime` (dims in the last seconds), and optional `IgniteSound`/`BurnLoopSound`/`BurnOutSound` (`UAudioComponent`).
  - `UsePrimary` → `Ignite()` (only from `Unlit`). A one-shot burn timer runs → `BurnOut()`: light off, mesh darkened,
    `CanBePickedUp` false, `SetLifeSpan(BurntOutLifeSpan)`. If held, the holder auto-drops it (`bAutoDropWhenBurntOut`).
  - Throwing a lit flare: it keeps burning on the floor and can be picked up again until it burns out.
  - `GetBurnTimeRemaining()` (BlueprintPure), `OnFlareStateChanged` delegate. `CallInEditor` button
    `DebugIgnite` for quick testing in the editor.

## Teaching notes to deliver with the code
Explain: `FObjectInitializer` and default subobject override; `UCameraModifier` vs. putting Tick on the character (compare
with Unity Cinemachine extensions); `UINTERFACE`/`BlueprintNativeEvent` vs. C# interfaces (the `Execute_` call form);
`TWeakObjectPtr` vs. `TObjectPtr`; timers vs. coroutines/`Invoke`; dynamic multicast delegates vs. C# events;
`UPrimaryDataAsset` vs. ScriptableObject; `UDeveloperSettings` vs. a Resources config asset; console variables.
