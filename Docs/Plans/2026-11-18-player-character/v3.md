## Differences from v2 during implementation

| v2 said | Built instead | Why |
|---|---|---|
| Camera-motion toggle via the console variable `eo.CameraMotion` | `UFUNCTION(Exec) SetCameraMotionEnabled` on `ASurvivorPlayerController` (console: `SetCameraMotionEnabled 0`) | A console variable is global and has no tidy way to reach each player's camera modifier. An `Exec` function on the controller is per-player and is the same call an options menu will make. |
| `Interaction` trace channel defaults to Ignore | Defaults to **Block**; the `Trigger` profile is set to Ignore | With Ignore, walls didn't block the trace, so you could pick items up through walls. Block lets the first hit win (walls occlude), and triggers are excluded. |
| The trace channel is set in `USurvivorSettings` | It's a property on `UInteractionComponent` | It's per-component configuration. The settings class only holds the camera-motion default. |
| Line trace | Small sphere sweep (`TraceRadius`, 4 cm) | Small items like flares are hard to hit with a thin line. |
| `UItemDefinition::HeldOffset` (FTransform) | `HeldLocationOffset` + `HeldRotationOffset` | A transform's scale would overwrite the placeholder mesh's root scale. Location and rotation are applied, and the item keeps its world scale. |
| Flare `CallInEditor DebugIgnite` | `CallInEditor TogglePreviewLight` | Igniting in the editor world would start timers and save a lit state into the level. Previewing the light covers the actual need (tuning it). |
| Flicker on a random timer | Perlin-noise flicker; strength doubles while fading out | Random values each update strobe instead of flickering. A sputter at the end reads as the flare dying. |
| — | Breathing motion in the camera modifier, stronger as stamina falls | Cheap extra tension that ties stamina to the camera feel. |
| — | Released items are pulled back to the player's side if the hand is inside a wall; items use continuous collision (CCD) | Stops dropped and thrown items passing through walls. |
| Test map built from scratch | `Lvl_ShipTest` is a copy of `Lvl_Horror`, plus 5 flares, a crouch-only beam and a GameMode override | The MCP tools can't create a new level. The horror grey-box is a good dark test space. |
| HUD in the widget Blueprint | `UI_SurvivorHUD` graph written via MCP: stamina bar (dims when exhausted), prompt, held item, flare bar and timer, inventory text row | Event-driven from `USurvivorHUDWidget`, with no per-frame bindings. |

## Follow-up changes requested after the first playtest

1. **Thrown flares flew too far when sprinting** (`b3a769b`). Released items inherited the full player velocity. Added
   `UItemDefinition::InheritedVelocityScale` (default 0.2).
2. **Our settings should be at the top of the Details panel** (`a76ba88`, `e6e2362`, `543f27f`):
   - `PrioritizeCategories` on its own couldn't do it. Subcategories (`Flare|Burn`) didn't match "Flare", and the
     engine's customizations (Static Mesh, Materials, Light, Rendering) always sort above anything it moves.
   - Created the **`EndlessOceanEditor`** module (v2 said it wasn't needed yet). `FPrioritizedCategoriesCustomization`
     uses `IDetailLayoutBuilder::SortCategories` to put a class's `PrioritizeCategories` directly under Transform.
     It's registered automatically for every EndlessOcean class that declares them.
   - Applied to items, character, controller, stamina, interaction, inventory, movement and the camera modifier.
     Camera modifier categories were renamed to `HeadBob`/`StrafeRoll`/`LookLag` (the list is space-separated), and the
     sprint settings moved to a `Sprint` category. `AHeldItem` hides engine categories that never apply.
   - The convention was added to CLAUDE.md (`c3e836a` on `main`).
